# InterviewTrace 首版需求草案

## 目标

在 Windows 个人电脑上录制线上面试，将音频转写为文字，再由用户复制或导出文字，交给其他 AI 工具进行复盘。

## 已确定的使用场景

- 面试时使用耳机。麦克风通常记录用户的声音，耳机输出对应的系统音频通常记录面试官的声音。
- 需要关注的是 Windows 中多个麦克风、耳机等音频设备的选择。
- 区分麦克风和系统音频两个声音来源即可；首版不要求区分多位面试官。
- 转写由用户在录音完成后手动触发，使用云端语音识别 API。无需在面试电脑本地运行语音识别模型。
- 转写结果用于后续复盘，应按时间排列，并标明声音来源，方便复制或导出到其他 AI 工具。
- 第一版需要手动管理面试记录；公司、岗位、日期和面试轮次等信息由用户自行填写和修改。
- 录音及转写文件的本地存储位置由用户手动指定，方便后续查找。

## 首版功能建议

1. 分别选择麦克风和面试软件使用的耳机输出设备，并检查两路声音是否有信号。
2. 开始、停止录音，显示录音状态和时长，分别保留两路音频及其时间关系，并在本地保存录音。
3. 用户点击“开始转写”后，向云端提交录音，显示处理状态。
4. 分别识别两路音频，按时间合并为一份带来源标记的面试记录。
5. 展示转写结果，支持复制或导出文本，并保留原始音频供回听和核对。
6. 提供面试记录列表，用户可以手动填写或修改记录信息，并重新打开关联的录音和转写文字。公司、岗位、日期和轮次等信息建议为可选，不影响开始录音。
7. 允许用户选择本地保存目录，在界面中查看保存位置并打开对应文件夹。

## 文件存储位置

- 用户可以设置默认保存目录，并在开始某次录音前为该次记录选择其他目录；界面应清楚显示当前选择。
- 每次录音对应的两路音频和生成的转写文字保存到用户选择的目录中。建议每次面试使用独立文件夹，便于查找；文字导出时可另选保存位置。
- 保存默认目录设置；重启软件后保留该设置。修改默认目录只影响之后的新记录，已有文件不自动移动或覆盖，历史记录仍指向原有位置。
- 如果保存目录不存在、不可写或空间不足，应明确提示用户并允许选择其他位置；录音中发生写入错误时，应提示并尽可能保留已经保存的内容。
- 如果历史文件被用户在软件外移动或删除，应明确显示文件不可用，并允许用户重新定位；不得静默删除历史记录。

## 音频设备选择与状态

- 界面分别提供“麦克风”和“耳机/扬声器”两个设备选择入口。前者采集选定的输入设备，后者采集选定播放设备的系统输出；如果耳机自带麦克风，其输入和输出也分别选择。
- 列出当前可用的设备，包括实际存在的虚拟设备；显示完整设备名称，并标识 Windows 默认设备。设备重名时提供足以区分的补充信息，不能只靠列表顺序或显示名称确定设备。
- 可以用 Windows 默认设备作为初始选择，但允许用户手动切换。面试软件可能被单独设置为使用其他设备，因此默认设备不一定就是面试实际使用的设备。
- 分别显示两路声音的活动状态或音量，并提供录音前的短暂试录与回听。正常静音不应直接判定为设备故障。
- 提供刷新设备列表的方式。选定设备不可用时要明确提示；录音中设备断开或采集失败时，要提示受影响的来源并保留已经录下的内容，不能静默切换设备并继续显示录音正常。
- “麦克风/系统音频”是两类声音来源；设备内部的左右声道或多通道属于另一层设置。首版以设备选择为主，不要求用户单独选择左右声道；具体设备的声道支持与映射需在真实设备上验证。
- 长录音建议持续或分段保存，异常退出后尽可能恢复已经写入的部分；可恢复范围需要在实际实现中验证。

## 首版验收要点

- 存在多个输入或输出设备时，可以明确选择实际使用的麦克风和耳机；录制和回听结果对应所选设备。
- 在麦克风说话、以及所选耳机播放声音时，界面能分别显示两路活动状态；试录时能分别听到两路声音。
- 拔出或禁用所选设备时能明确提示；录音中发生此类故障后，已录制的内容仍可用。
- 停止录音后，音频可在本地找到并回听；未手动点击转写时，不自动提交云端转写。
- 转写结果按录音时间排序，能够区分麦克风来源和系统音频来源。
- 云端转写失败时，原始录音仍然可用，用户可重新发起转写。
- 转写文字可以复制或导出，用于其他 AI 工具。
- 重启软件后仍可查看已保存的面试记录及其关联的录音、转写文字，并可手动修改记录信息。
- 选择的保存目录和单次录音的其他目录均能生效，录音及转写文件可从显示的位置找到；重启软件后默认保存目录仍然有效。
- 修改默认保存目录后，旧文件仍留在原处且历史记录可访问；导出文字时可自行选择另存位置。
- 指定不可用或不可写目录时，软件会提示并允许更换；历史文件被移动后能提示并重新定位。

## 实现时需要验证

- 所选 Windows 音频设备能否与面试软件同时使用，以及长时间录音时两路音频的同步情况。
- 会议软件可能使用与 Windows 默认设备不同的输入或输出；需要在实际设备上验证名称、选择及输出采集是否匹配。参考微软关于[默认音频设备选择](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/default-audio-endpoint-selection)和[输出设备环回采集](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)的说明。
- 设备标识在系统或驱动更新后可能变化；需要处理设备重新识别及选择恢复失败的情况。参考微软的[音频设备标识说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/endpoint-id-strings)。
- 云端接口对长音频、时间戳、分轨识别及文件上传的支持；具体服务和模型根据测试确定。
- 麦克风与系统音频分别识别时的实际计费，以及云端文件上传可能涉及的额外费用。
- 系统音频还可能包含通知声或其他应用的声音；来源标记不等于对真实说话人身份的识别。

## 后续可考虑的功能（尚未确定）

- 复盘标记与笔记：回听时标记某个时间点，记录需要复习的题目或回答问题。
- 转写校对：允许修改文字，并根据实际选用的语音识别服务考虑专业术语热词。
- 导入已有录音：把过去的面试录音转成文字。若音频原本未分开保存双方来源，不能仅凭导入保证区分双方。
